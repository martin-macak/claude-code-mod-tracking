# Gotchas

Pitfalls a mod author hits. Read this before you write mod code. Rows 1 to 34 are pinned to Claude Code 2.1.295. Some carry a **2.1.302** note. Rows 35 and up were added for 2.1.302. Row numbers stay fixed, because other pages cite them. Each item links to its source or to the KB page with detail.

Grades on a 2.1.302 note: *verified-live* (seen in an interactive session), *verified-kit* (seen in `claude plugin validate`, `claude plugin test`, `tsc`, or a headless `claude -p` run against a fake API), *types-only* (the d.ts or `reference.md` says it, nobody ran it), *inference*. The evidence is on the linked page. See [changes-2.1.302](reference/changes-2.1.302.md) for everything that moved since 2.1.295.

## Files and config

| # | Gotcha | Do this | Source |
| --- | --- | --- | --- |
| 42 | `$.fs.write` overwrites **in place**. It is not a temp file plus rename. A reader can see old and new text mixed, or a truncated prefix, for a large file. Two sessions on one file are last writer wins. There is no lock (*verified-live*, macOS APFS). | Keep a shared file small (a few KiB). Treat a parse failure as transient: keep the last good value and retry once. Compare `mtimeMs` plus `size` to detect a change. | [fs-and-config](reference/fs-and-config.md#torn-reads-and-mtime) |
| 43 | `~` is not documented as expanded in `$.fs`. The `stat` doc lists `~` among the spellings the engine cannot resolve. Nobody ran it (*types-only*, *inference*). `$.env.get` takes a **literal** name. | Build the path from `await $.env.get('HOME')`. `validate` lists the names it reads. A path under `~/.config` wrote with no prompt (*verified-live*). | [fs-and-config](reference/fs-and-config.md#scope-and-paths) |
| 44 | `$.fs` has no delete, rename, mkdir, append, chmod, lock or watch. A read or write over 4 MiB rejects. Every call is an event (`fs.read`, `fs.write`, ...) that another plugin's hook can deny, and a managed `plugin.register` policy may refuse a module that calls `fs.write` (*types-only*). | Handle a rejection from every call. Do not plan on delete or atomic replace. | [fs-and-config](reference/fs-and-config.md#every-call-is-an-event) |
| 45 | A config file read through `$.fs` needs care. `XDG_CONFIG_HOME` counts only when it is non-empty and absolute (XDG spec). A library default such as `configstore`'s `clearInvalidConfig` overwrites a hand-edited file that fails to parse. A cache keyed on `mtimeMs` alone can miss two edits in one tick (*inference* from the XDG spec and the library docs named on the linked page). | Accept `XDG_CONFIG_HOME` only if absolute. Never write over an invalid file. Key the cache on `mtimeMs` and `size`. Use an integer `version` key and a `.bak` copy for migrations. | [config-manager](../claude-code-mod-architecture/config-manager.md#5-options-and-trade-offs) |
